**Skill 名称**  
LoveEngine Witness 2.0

**Skill 定位**  
一个围绕 UAS 见证方案 2.0 运行的治理型 Skill。它不是普通问答助手，而是把注册、排期提醒、直播见证、证据整理、提案表决、争议处理和总账核验整合在一起的“见证工作站”。

**Skill 的核心目标**  
第一，让见证者低摩擦参与。  
第二，让直播见证有统一的任务流和证据流。  
第三，让投票表决标准化，而不是靠临场情绪。  
第四，让公众能看到总账变化和企业补偿结果。  
这和旧稿里“教育、度量、治理、直播协调、协议管理”几类能力是一脉相承的，只是现在收敛到见证 2.0 这一条主线上。

**Skill 核心模块**

模块一，见证者注册与参与模块。  
作用是完成 Skill 初始化、钱包绑定、基本身份确认、见证任务订阅、退出登记。你当前稿子已经把注册、钱包、退出写进来了，但结构还太实现导向。

模块二，直播排期与提醒模块。  
作用是读取 `CorporateSink` 的直播排期，给见证者推送提醒、预加载本场提案背景、同步倒计时。这个模块决定“人人见证”会不会沦为空话，因为开放参与最怕没人按时到场。

模块三，直播见证与证据整理模块。  
作用是接入文字直播、视频直播、屏幕截图、关键操作清单、时间戳记录，并自动整理成“本场见证摘要”。你文稿里已经提出文字和视频并行，这非常对，Skill 就该把这部分变成标准化证据包。

模块四，提案阅读与投票模块。  
作用是把“新用户数提案”转成可读的投票界面，显示提案内容、证据摘要、争议点、投票窗口、当前参与人数、赞成比例、是否达到最小参与门槛。这里必须明确显示通过条件，不然每个见证者脑内都有一套数学。

模块五，公众意见与争议处理模块。  
作用是收集公开反馈、聚类争议、标记异常、形成“支持 / 反对 / 待核实”三类摘要。旧 Skill 稿里已经强调“意见采集”和“高价值反馈筛选”，这一块在 2.0 里应该保留，但要服务于见证，不要泛化成空泛舆情平台。

模块六，总账与企业补偿看板模块。  
作用是显示 `PublicSink` 总账增长、提案通过后的流速变化、 `CorporateSink` 状态。你当前流程只写了总账增长，Skill 里最好把企业补偿也并列展示。

模块七，PoL 说明与见证教育模块。  
作用是解释 UAS、UTO、见证规则、为什么要直播、为什么要 90% 门槛、为什么 UTO 是公开记账工具而不是自由货币。简化的 PoL 教育引擎。没有它，新见证者会像被突然扔进多签现场的路人。

**Skill 的完整流程**

流程一，注册参与。  
用户安装或打开 Skill，成为注册见证者。若暂不参与，可保持观察者状态；若要退出，则在 Skill 内完成退出。

流程二，直播前准备。  
支付公司代理人提前登记直播排期；Skill 自动读取排期并提醒见证者，展示本场提案背景、上次结果、待核验指标和注意事项。

流程三，直播中见证。  
Skill 同步视频流、文字流和关键操作清单，自动记录时间戳，辅助见证者标记“已展示 / 未展示 / 可疑”事项，生成见证摘要草稿。

流程四，直播后投票。  
Skill 打开 24 小时投票窗口，展示提案内容、证据摘要、争议点和通过条件。见证者完成投票，系统实时显示有效参与人数和赞成比例。

流程五，提案结算与账本变更。  
提案通过后，Skill 展示 `StreamingEngine` 参数更新结果、总账变化趋势以及该次提案对应的账本影响。

流程六，成本补偿审批。  
支付公司如申请补偿，Skill 展示申请理由、证据材料、见证摘要和审批结果，并在 `CorporateSink` 与总账看板中同步呈现。这一条现在你文档没单列，但 Skill 里最好必须有。
