一次前向计算，如何推进多个 token？

Multi-Token Prediction（多 token 预测，MTP）让模型学习对多个未来 token 提前提出候选；它的工程价值不在于跳过验证，而在于让目标模型一次验证更长的候选前缀。这页把训练目标、模型模块与 speculative decoding（投机解码）拆开说明。

一手论文与官方文档 可交互机制演示 性能数字均保留测试条件 不把论文结果外推为通用承诺
一句话带走

MTP 是更好的提议能力；投机解码是由目标模型验证并接纳提议的流程。只有验证规则正确，速度提升才不会以输出语义为代价。

请把“能提议多个 token”与“能安全提交多个 token”视为两个不同问题。

先对齐词义

三个词，三个层次

会议里最容易混淆的是把“训练时预测多个未来位置”直接等同于“推理时一次输出多个 token”。两者中间还必须有候选验证。

自回归解码

传统 LLM 先生成下一个 token，再把它加入上下文，继续生成下一个。依赖关系让解码天然串行。

回答：目标模型每步“决定一个”。

MTP

训练目标或模型模块：从同一段上下文，对未来多个位置给出候选分布。实现可用独立 heads，也可用保持因果链的顺序模块。

回答：模型可以“多提几个建议”。

投机解码

服务算法：使用较快的候选来源，再让目标模型并行验证候选前缀；接受的部分前进，拒绝处由目标模型纠正。

回答：系统决定“哪些建议可以采用”。

MTP 可作为训练辅助目标

论文采用共享 trunk 和多个独立输出 heads，在同等参数预算下比较。作者报告：13B 代码模型相对基线在 HumanEval 解题数高 12%，在 MBPP 高 17%。

这是该论文的实验结论，不是每个模型、语言或任务的普遍规律。
同一论文中的反例

预测更远不总是更好

该研究的 7B 自然语言实验中，预测 2 个未来 token 在选择题基准大体持平，而预测 4 个未来 token 出现退化。

候选步长和损失权重是要被验证的设计变量，不是可以照搬的默认值。
公开模型报告 | DeepSeek-V3

把 MTP 作为训练目标，也可复用为草稿模块

DeepSeek-V3 采用保持完整因果链的顺序 MTP，区别于独立 heads；报告称第二 token 的接受率在不同主题为 85% 到 90%，并报告 1.8 倍 TPS。

这是该模型、其解码配置和报告口径下的数字，不能替代自己的基准测试。

模型权重与服务实现已经衔接

短答案，但不省略边界

这些回答以公开论文和官方实现文档为依据；不同模型或供应商的宣传数字不应替代这组问题的实际测量。

MTP 是否让 LLM “一次真实生成多个 token”？

它可以同时提出多个未来位置的候选，但自回归语义仍需要确认候选之间的依赖。工程上通常由目标模型验证候选前缀；接纳前的多 token 是提议，不是最终输出。

MTP 与 speculative decoding 是同一件事吗？

不是。MTP 是训练目标或模型侧候选模块；speculative decoding 是服务算法。后者还可以使用小草稿模型、N-gram 或 EAGLE 等其他候选来源。

能不能在任意已经训练好的 LLM 上只加几个 heads？

不能把它当作低成本确定方案。2025 年研究发现，预训练为 next-token prediction 的隐藏层会对 NTP 专化，单独训练新 heads 的适配并不容易；联合训练有改善，但仍有差距。

验证后为什么还可能没有加速？

接受率低、草稿成本高、候选树占显存、batch 变大、context 很长，或内核和调度不匹配，都可能吞掉收益。应当用目标业务的 TTFT、TPOT、吞吐和显存一起比较，而不是只看接受率。

“输出不变”是什么意思？

经典投机解码论文的结论是：采用正确的接受与重采样规则后，可以保持目标模型的采样分布。若温度或随机种子不同，单次文本当然可能不同；若跳过验证或改变规则，则不能再声称保持该语义。
